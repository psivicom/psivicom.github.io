01 — How Does a Binary File Get a .psvc Extension?

The Simple Answer
File Extensions Are Just Names
A file extension like .psvc is simply a naming convention. It tells the operating system and applications what kind of file this is, but it doesn't change the file's actual content.

Any binary file can have any extension. A .psvc file is a binary file that follows the RFC 1001 specification and is named with the .psvc extension so that software knows how to read it.

Analogy: File Extensions Are Like Labels

Think of a file extension like a label on a jar:

  • A jar labeled "Honey" contains honey
  • A file labeled data.psvc contains .psvc-formatted binary data
  • You could put sand in a jar labeled "Honey", but it would be wrong
  • Similarly, you could name a text file image.psvc, but software would reject it

How Software Knows It's Real

Software doesn't trust the extension alone. It reads the magic bytes at the start of the file:

$ xxd example.psvc | head -1
00000000: 5053 5649 0100 0010 0000 0087 0000 0078  PSVI.........x

Bytes 0-3: "PSVI" (0x50 0x53 0x56 0x49)
This proves it's a real .psvc file.

If the magic bytes are wrong, the software rejects the file regardless of the extension.

02 — How Do You Create a .psvc Container?

Creating a .psvc file is a 3-step process: encode the data as a vector → compress it → write it with the header. Here's the actual Python code from the Mesh Pico AI repository:

import numpy as np
import struct
import zlib
import hashlib

def create_psvc_container(vector, output_path, precision="int8"):
    """
    Creates a .psvc binary container from a numpy vector.
    
    Args:
        vector: numpy array of shape (4096,) containing float32 values
        output_path: where to save the .psvc file
        precision: "int8", "float16", or "float32"
    """
    
    # Step 1: Compress the vector based on precision
    if precision == "int8":
        # Quantize to INT8 with scale factor
        scale = np.max(np.abs(vector)) / 127.0
        if scale == 0: scale = 1.0
        quantized = np.round(vector / scale).astype(np.int8)
        payload = struct.pack('f', scale) + quantized.tobytes()
        precision_code = 0
    elif precision == "float16":
        # Convert to half-precision
        payload = vector.astype(np.float16).tobytes()
        precision_code = 1
    else:  # float32
        # Keep full precision
        payload = vector.astype(np.float32).tobytes()
        precision_code = 2
    
    # Step 2: Compress with zlib (maximum compression)
    compressed_payload = zlib.compress(payload, level=9)
    
    # Step 3: Build the 14-byte header
    header = b'PSVI'  # Magic bytes (4 bytes)
    header += struct.pack('B', 1)  # Version 1 (1 byte)
    header += struct.pack('B', precision_code)  # Precision (1 byte)
    header += struct.pack('I', len(vector))  # Dimensions (4 bytes, uint32)
    header += struct.pack('I', len(compressed_payload))  # Payload size (4 bytes, uint32)
    
    # Step 4: Write to file with .psvc extension
    with open(output_path, 'wb') as f:
        f.write(header + compressed_payload)
    
    return output_path

# Example usage:
vector = np.random.randn(4096).astype(np.float32)
vector /= np.linalg.norm(vector)  # Normalize

create_psvc_container(vector, "observation_a16330272f3f.psvc", precision="int8")
print("Created: observation_a16330272f3f.psvc")

Why the filename is a16330272f3f.psvc: The filename is derived from the SHA-256 hash of the uncompressed vector, truncated to 12 hex characters. This ensures that identical vectors always produce identical filenames, enabling automatic deduplication across the Git-based memory bus.

03 — How Do You Validate a .psvc File?

Before reading a .psvc file, software must validate it to ensure it's not corrupted or malicious. This is a 4-step process:

def validate_psvc(file_path):
    """
    Validates a .psvc file before reading it.
    Returns True if valid, False if corrupted or malicious.
    """
    
    with open(file_path, 'rb') as f:
        # Step 1: Check file size (minimum 14 bytes for header)
        f.seek(0, 2)  # Seek to end
        file_size = f.tell()
        if file_size < 14:
            print(f"[INVALID] File too small: {file_size} bytes")
            return False
        f.seek(0)  # Back to start
        
        # Step 2: Check magic bytes
        magic = f.read(4)
        if magic != b'PSVI':
            print(f"[INVALID] Wrong magic bytes: {magic}")
            return False
        
        # Step 3: Read header
        version = struct.unpack('B', f.read(1))[0]
        precision = struct.unpack('B', f.read(1))[0]
        dimensions = struct.unpack('I', f.read(4))[0]
        payload_size = struct.unpack('I', f.read(4))[0]
        
        # Step 4: Validate payload size matches actual file
        expected_size = 14 + payload_size
        if file_size != expected_size:
            print(f"[INVALID] Payload size mismatch: expected {expected_size}, got {file_size}")
            return False
        
        print(f"[VALID] Version {version}, Precision {precision}, {dimensions} dims, {payload_size} bytes")
        return True

# Example usage:
if validate_psvc("observation_a16330272f3f.psvc"):
    print("File is safe to read")
else:
    print("File is corrupted or malicious - DO NOT READ")

What Validation Catches

  • Wrong magic bytes: File is not a .psvc (might be renamed malware)
  • File too small: Corrupted download or incomplete write
  • Payload size mismatch: File was truncated or tampered with
  • Invalid precision code: Unknown format version

Why This Matters

In a decentralized mesh with volunteer nodes, you cannot trust files from unknown sources. Validation ensures:

  • No buffer overflow attacks (size is checked before reading)
  • No code injection (payload is only numeric data)
  • No corrupted data (size must match exactly)
  • No format confusion (magic bytes must be "PSVI")

04 — How Do You Control What Goes In and Out?

The .psvc format uses a sealed container model. Data goes in compressed and dormant, and only decompresses when explicitly called into active VRAM. Here's how the mesh controls input and output:

class PicoContainer:
    """Controls what goes in and out of .psvc containers."""
    
    def __init__(self, file_path):
        self.file_path = file_path
        self._open_vector = None  # None = sealed (closed)
    
    def open(self):
        """Open the container: decompress into active VRAM."""
        if self._open_vector is not None:
            return self._open_vector  # Already open
        
        with open(self.file_path, 'rb') as f:
            # Skip magic, version, precision
            f.read(6)
            
            # Read dimensions and payload size
            dimensions = struct.unpack('I', f.read(4))[0]
            payload_size = struct.unpack('I', f.read(4))[0]
            
            # Read precision code (we need to rewind)
            f.seek(5)
            precision_code = struct.unpack('B', f.read(1))[0]
            
            # Read compressed payload
            f.seek(14)
            compressed_payload = f.read(payload_size)
        
        # Decompress
        payload = zlib.decompress(compressed_payload)
        
        # Convert back to float32 based on precision
        if precision_code == 0:  # INT8
            scale = struct.unpack('f', payload[:4])[0]
            int8_data = np.frombuffer(payload[4:], dtype=np.int8)
            self._open_vector = int8_data.astype(np.float32) * scale
        elif precision_code == 1:  # Float16
            self._open_vector = np.frombuffer(payload, dtype=np.float16).astype(np.float32)
        else:  # Float32
            self._open_vector = np.frombuffer(payload, dtype=np.float32).copy()
        
        return self._open_vector
    
    def close(self):
        """Seal the container: release VRAM, keep file on disk."""
        self._open_vector = None
    
    @property
    def is_open(self):
        """Check if container is currently in active VRAM."""
        return self._open_vector is not None

# Example usage:
container = PicoContainer("observation_a16330272f3f.psvc")

# OPEN: Load into VRAM (only when needed)
vector = container.open()
print(f"Vector loaded: {vector.shape}, norm: {np.linalg.norm(vector):.4f}")

# Do math with the vector
similarity = np.dot(vector, query_vector)
print(f"Similarity: {similarity:.4f}")

# CLOSE: Release VRAM (file stays on disk)
container.close()
print(f"Container sealed. VRAM freed.")

Input Control (What Goes In)

Only the Mesh Router can call open() on a container. This happens when:

  • A query matches the container's content (similarity search)
  • The Cortex Agent is clustering vectors (K-Means)
  • The Critic Agent is comparing predictions

Pico Limit: The Governor Agent enforces a maximum of 5 open containers at once. If a 6th is requested, the oldest is automatically closed (LRU eviction).

Output Control (What Comes Out)

When a container is opened, it returns a read-only numpy array. The original file on disk is never modified.

  • Volunteer nodes can read vectors
  • Volunteer nodes can compute with vectors
  • Volunteer nodes cannot modify the sealed container
  • New results are written as new .psvc files

This ensures immutable audit trails. Every observation is preserved forever.

05 — How Safe Is the .psvc Format?

Security Model: Defense in Depth
The .psvc format uses multiple layers of security to protect against malicious files, corrupted data, and unauthorized modifications. Here's how each layer works:

Layer 1: Magic Bytes

Threat: Malicious file disguised as .psvc

Defense: Software checks bytes 0-3 for "PSVI". If wrong, file is rejected immediately.

if magic != b'PSVI':
    reject()

Layer 2: Size Validation

Threat: Buffer overflow attack

Defense: Header declares exact payload size. If file is larger/smaller, it's rejected.

if file_size != 14 + payload_size:
    reject()

Layer 3: Content Addressing

Threat: Tampered data

Defense: Filename is SHA-256 hash of vector. If content changes, hash changes, filename changes.

hash = SHA256(vector)
filename = hash[:12]

Layer 4: No Code Execution

Threat: Code injection

Defense: Payload is only numeric arrays. No strings, no code, no scripts. Impossible to execute.

payload = np.array([...])
# No eval(), no exec()

Layer 5: VRAM Limits

Threat: Denial of Service (memory exhaustion)

Defense: Governor enforces max 5 open containers. Oldest evicted automatically.

if len(open) >= 5:
    evict_oldest()

Layer 6: Entropy Pruning

Threat: Repository bloat

Defense: Cortex deletes vectors >95% similar to master states. Keeps only novel data.

if similarity > 0.95:
    delete()
The Bottom Line
.psvc Is Safe by Design
The .psvc format is safe for volunteer nodes because:
  • It contains only numbers—no executable code, no scripts, no strings
  • It's validated before reading—corrupted or malicious files are rejected
  • It's immutable—once sealed, it cannot be modified
  • It's memory-limited—only 5 containers can be open at once
  • It's cryptographically signed—the filename proves the content hasn't changed

A volunteer node can safely process thousands of .psvc files without risk of infection, data corruption, or resource exhaustion. The format was designed from the ground up for decentralized, untrusted environments.
